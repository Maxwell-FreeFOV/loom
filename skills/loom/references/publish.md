# publish：发布知识库快照

目标：把知识库中可以公开的内容打包成一个 zip，交给合作者。对方拿到的是这一时刻的状态和结果，不包含对话记录、会话纪要、决策记录、时间线和日志，也接触不到知识库本身。对方有更新时，把他的快照用 ingest 导入即可，见 `ingest.md`。

发出去的内容收不回来。第 4、5 步的审阅和确认不能省略。

## 步骤

1. **准备**
   - 快照默认写到 `50-Outputs/_exports/`。如果项目没有启用 outputs 模块，先建议用户启用（见 `module.md`）。
   - 运行 `git status --porcelain`。有未提交的改动时，先问用户是否提交；用户不提交的，记下来，它们不属于本次发布，第 7 步提交时不要带进来。

2. **确认发布规则**：运行 `$PY "$LOOM/scripts/snapshot.py" plan`，输出的第一节是当前生效的规则。
   - 如果显示"默认值"，说明这个项目还没有配置过。把默认规则讲给用户听，按用户的意见调整，然后写进 `.kb.json` 的 `publish`：
     ```json
     "publish": {
       "include": ["10-Brief/", "30-Wiki/", "20-Sources/cards/", "50-Outputs/", "00-Hub/roadmap.md"],
       "exclude": [],
       "strip_fields": ["raws", "session", "commits", "decisions"],
       "strip_sections": ["变更记录", "版本历史"]
     }
     ```
   - `include`、`exclude`：以 `/` 结尾的是目录，否则是文件路径，可以用 `*` 通配。`exclude` 优先于 `include`。
   - `strip_fields`：从笔记的 frontmatter 中删除的字段。`strip_sections`：从正文中删除的段落标题。
   - 单篇笔记可以在 frontmatter 中写 `publish: false` 排除，或写 `publish: true` 强制发布（优先于上面的规则）。
   - 状态不是 `released` 的产出物默认不发布。
   - 硬性排除的路径（`plan` 会列出）不能通过配置或 `publish: true` 打开。

3. **看预览**：`plan` 还会列出：
   - 将发布的文件，标注"新"、"改"或"未变"（相对 `50-Outputs/_exports/` 中的上一份快照）；
   - 在发布范围内但被排除的笔记及原因；
   - 需要留意的内容：本机路径、邮箱、密钥类内容、对话记录路径。

4. **审阅内容**：阅读标为"新"和"改"的笔记，以及"需要留意"中列出的条目。"未变"的笔记上次已经审阅过，不用再读。找出以下内容，列给用户：
   - 敏感信息：个人信息、账号和密钥、第三方的保密内容、不想让对方知道的判断；
   - 过程信息：对讨论过程的转述、被否决的方案的细节、"上次会话中……"这类只对自己有意义的说法。
   
   每一条由用户决定怎么处理：
   - 整篇不发布：在这篇笔记的 frontmatter 中加 `publish: false`；
   - 修改措辞：直接改知识库中的源文件；
   - 照常发布。
   
   脚本只做机械的清洗，不会改写正文。决策记录不会发布，所以需要让对方知道的理由，应当写在 wiki 页或产出物里。

5. **请用户确认**：改动之后重新运行 `plan`，把最终的文件列表给用户看。得到明确的确认之后才能继续。

6. **生成快照**：运行 `$PY "$LOOM/scripts/snapshot.py" build`，记下输出的 zip 路径。

7. **收尾**
   - 在 `00-Hub/log.md` 中追加一行；在 `00-Hub/timeline.md` 末尾追加 `- YYYY-MM-DD · 发布知识库快照（给谁，如果用户说了）`。
   - 提交：只 `git add` 本次涉及的具体文件（不要用 `git add -A`），`git commit -m "publish: 快照 YYYY-MM-DD"`。本次涉及的文件包括 `loom.py status` 补导出到 `40-Sessions/raw/` 的原始对话：它们是 Loom 自己生成的，始终随这次提交。开始时记下的既有改动不要带进来；如果某个文件里混有无法分离的用户既有改动，不提交这个文件，向用户说明原因。
   - 打 tag：`git tag publish/YYYY-MM-DD`。同一天发布多次时，在后面加 `-2`、`-3`。
   - 告诉用户 zip 的位置。怎么发给对方（邮件、网盘、即时通讯）由用户决定，AI 不代为发送。
