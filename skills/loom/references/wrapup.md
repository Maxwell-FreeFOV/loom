# wrapup：会话归档

目标：以后的自己和 AI 不必重读原始对话，就能知道这次讨论得出了什么、改变了什么。

## 步骤

开始之前先运行 `git status --porcelain`，记下此刻已经存在的改动：它们不属于本次归档，第 8 步提交时不要带进来。`40-Sessions/raw/` 下的原始对话除外，见第 8 步。

1. **找出待归档的会话**
   - `loom.py status` 已经补导出了对话，并列出了未归档的会话。其中通常包括本次会话，也可能有以前忘记归档的。需要完整列表时，运行 `$PY "$LOOM/scripts/kb.py" unarchived`。
   - 逐个判断：
     - 有实质内容：写纪要。同一主题的多个会话可以合并成一份纪要。
     - 没有实质内容（试运行、闲聊、中途放弃）：在 `40-Sessions/notes/_skipped.md` 里加一行链接，不写纪要。
   - 待归档的会话超过 3 个时，先把列表和处理建议交给用户确认。
   - 只是补归档以前的会话（用户在会话开始时答应补归档，接着要做别的事）时：归档只依赖 `40-Sessions/raw/` 里的文件，不依赖当前对话。工具支持子代理时，把它交给子代理在后台做，主会话继续用户的事情，完成后再向用户报告。
   - 如果不在 Claude Code 中，本次对话不会被导出：纪要直接根据当前对话来写，`raws` 留空。

2. **写会话纪要**：用 `loom.py template 会话纪要` 找到模板，新建 `40-Sessions/notes/YYYY-MM-DD_主题.md`，日期用会话发生的日期。
   - `raws` 列出对应的原始对话，例如 `raws: ["[[2026-01-01_1030_abcd1234]]"]`。
   - `summary` 写一句话结论（这次得出了什么，不是讨论了什么）。它会显示在索引里，让以后不打开纪要就能判断相不相关。写成单行，不要含 ` #`。
   - `tags` 用 3 到 6 个标签，方便以后 grep。
   - 只写实质内容：结论、洞察、分歧和行动，不要复述对话过程。用户的关键原话可以少量引用。

3. **写决策记录**（仅当本次形成了决定，或者明确出现了一个待决定的重要事项时）
   - 编号：扫描 `40-Sessions/decisions/`，取当年最大编号加 1，格式为 `DR-YYYY-NNN`。
   - 用"决策记录"模板新建 `40-Sessions/decisions/DR-YYYY-NNN_主题.md`，并在纪要的 `decisions` 中链接它。
   - `review_date` 的默认值：可逆决策为 1 个月后，不可逆决策为 3 个月后。用户指定了日期的，以用户为准。
   - 信心度和"放弃了什么"必须填写。讨论中没有明确的，就问用户。

4. **更新 wiki**：本次形成的新事实、新理解、调研结论，写进 `30-Wiki/` 中对应的主题页。没有合适的页面，就用"wiki页"模板新建。每个论断都注明来源（资料卡、原始资料或本次纪要）。纪要里只保留结论和指向 wiki 的链接，避免同一内容在两处展开。

5. **更新时间线和路线图**
   - 本次有里程碑（重要决定、阶段切换、产出物发布、代码里程碑、关键发现）时，在 `00-Hub/timeline.md` 末尾追加 `- YYYY-MM-DD · 事件 · [[链接]]`。
   - 在 `00-Hub/roadmap.md` 中勾掉已完成的任务，加入新任务。已完成的里程碑移到 timeline。

6. **检查产出物的关联**（有 `50-Outputs/` 时）：本次修改过的、或者作为依据的产出物，更新它们 frontmatter 中的 `sources`、`decisions` 和 `updated`。如果正式发布了某个版本，按通用规则第 9 节打 tag，并记入 timeline。

7. **更新 `00-Hub/hot.md`**：当前阶段、当前重点、未决问题（加入新的，删掉已解决的）、最近的决定，以及 frontmatter 中的 `updated`。控制在一页以内。

8. **收尾**
   - 在 `00-Hub/log.md` 的注释行下方追加 `- YYYY-MM-DD HH:MM · wrapup · [[纪要]] [[决策]]`。
   - 运行 `$PY "$LOOM/scripts/kb.py" index`，再运行 `$PY "$LOOM/scripts/kb.py" lint`，修复本次引入的问题。
   - 提交：只 `git add` 本次涉及的具体文件（不要用 `git add -A`），`git commit -m "wrapup: 主题"`。本次涉及的文件包括 `loom.py status` 补导出到 `40-Sessions/raw/` 的原始对话：它们是 Loom 自己生成的，始终随这次提交。开始时记下的既有改动不要带进来；如果某个文件里混有无法分离的用户既有改动，不提交这个文件，向用户说明原因。
   - 向用户简要报告：生成或修改了哪些文件，以及 3 条以内的核心结论。请用户确认有没有记错。
