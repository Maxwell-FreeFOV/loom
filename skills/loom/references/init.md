# init：把当前文件夹初始化为 Loom 项目

原则：
- **不移动、不删除用户已有的文件**，除非用户明确同意。
- 每一步都要能用 git 回滚。
- 能从已有资料里推断出来的信息就不再提问，直接请用户确认。

## 0. 前置检查

- 当前目录就是要初始化的项目根目录。如果用户想在别处建项目，请用户先切换过去，或者用 `--root` 参数指定目录。
- 如果 `loom.py status` 输出了知识库根目录，说明这里已经是 Loom 项目，或者位于某个 Loom 项目之内。这时停下来：
  - 已经是 Loom 项目：说明不需要初始化；
  - 位于其他 Loom 项目之内：请用户在那个项目之外另建文件夹。

## 1. 盘点现状

- 列出当前目录下的内容（文件数量、类型、目录结构、总大小），据此判断起点：
  - 空目录：从一个想法起步；
  - 有文档、PDF、网页存档等：从已有资料起步；
  - 有代码：很可能需要 engineering 模块。
- 如果当前目录本身就是一个代码仓库（有 `.git`，内容主要是代码），**先停下来问用户**。Loom 知识库应当放在外层：建议另建一个项目文件夹，把这个代码库放进它的 `repos/` 下。
- 如果目录里已有文件，但还不是 git 仓库，先做一个快照，便于回滚：`git init && git add -A && git commit -m "初始化前的原始状态"`。

## 2. 访谈

用提问工具（例如 Claude Code 的 AskUserQuestion）提问，最多两轮，每轮不超过 4 个问题：

1. 项目名称（默认用文件夹名）和一句话描述。
2. 项目性质。这决定启用哪些模块，可以多选，以后也能再加：
   - 想法孵化：只用 core；
   - 研究调研：加上 `research`；
   - 工程开发：加上 `engineering`；
   - 需要产出设计文档或报告：加上 `outputs`。
3. 已有资料在哪里：就在本文件夹 / 在其他路径（请用户给出）/ 暂时没有。
4. 关联的代码库（只在启用 engineering 时问）：远端地址或本地路径，以及各自的用途。

然后通过自然对话，补充写项目简报需要的信息：要解决的问题、目标与成功标准、范围、约束、时间预期。说不清的地方可以先空着，以后再补。

## 3. 安装

```
$PY "$LOOM/scripts/loom.py" init --name "<名称>" --summary "<一句话描述>" [--modules <模块，逗号分隔>]
```

阅读输出的报告。如果出现"已存在同名文件"，说明模板被写成了 `<文件>.loom-new`：把其中的内容合并进原文件，然后删除 `.loom-new`。拿不准时问用户。

## 4. 整理已有资料（没有资料就跳过）

- **资料就在本文件夹**：不要移动。在 `20-Sources/sources-index.md` 中逐项登记，链接指向原来的位置，状态记为"已编目"。然后问用户：要不要移进 `20-Sources/raw/`，让目录更整洁？用户同意后，用 `git mv` 移动（第 1 步做过快照，可以回滚），并更新清单中的链接。
- **资料在其他路径**：复制（不是移动）到 `20-Sources/raw/`，保留原来的子目录结构，然后登记。
- **资料很多**（超过约 30 份）：按子目录或类型分组编目，只给最重要的资料写一句话摘要。
- 和用户一起挑出最重要的几份（不超过 5 份），按 `ingest.md` 的第 4、5 步写资料卡，建立最初的 wiki 页。其余资料的状态记为"待读"，以后分批 ingest。

## 5. 填写项目内容

安装步骤已经生成了下列文件的框架，根据访谈和资料把它们填完整：

- `10-Brief/项目简报.md`：问题、目标与成功标准、范围、约束、关键假设、已有基础。**写完后请用户确认。**
- `AGENTS.md`：填写"项目概况"和"项目特有约定"两节。不要改动 `<!-- loom:begin -->` 和 `<!-- loom:end -->` 之间的内容。
- `00-Hub/hot.md`：一句话描述、当前阶段、当前重点、未决问题。
- `00-Hub/roadmap.md`：最初的几项任务和第一个里程碑。
- `00-Hub/timeline.md`：保留"项目启动"这一条。如果资料中有已知的重要历史节点，可以补进来，并注明日期的出处。

## 6. 关联代码库（仅在启用 engineering 时）

1. 在 `repos.yaml` 中登记每个代码库。
2. 运行 `$PY "$LOOM/scripts/sync_repos.py"`，克隆缺失的代码库，并查看状态。
3. 在 timeline 中记录各代码库当前的 commit。

## 7. 归档本次会话，然后提交

1. 运行 `$PY "$LOOM/scripts/export_session.py" --all`，导出本次会话。这一步只在 Claude Code 中有效，在其他工具中跳过。
2. 用 `loom.py template 会话纪要` 找到模板，为这次初始化写一份纪要：`40-Sessions/notes/YYYY-MM-DD_项目初始化.md`。如果第 1 步导出了原始对话，在 `raws` 中链接它。
3. 在 `00-Hub/log.md` 中追加一行：`- YYYY-MM-DD HH:MM · 初始化 · [[项目简报]]`。
4. 运行 `$PY "$LOOM/scripts/kb.py" index` 和 `$PY "$LOOM/scripts/kb.py" lint`，修复发现的问题。
5. 如果还不是 git 仓库，先 `git init`；然后执行 `git add -A && git commit -m "loom: 初始化项目 <名称>"`。

## 8. 向用户交代

简要告诉用户：

- 创建了哪些目录和文件，启用了哪些模块。
- 可以用 Obsidian 把这个文件夹作为 vault 打开。
- 日常用法：
  - 讨论结束时做 wrapup（Claude Code 中是 `/loom wrapup`）；
  - 新资料放进 `20-Sources/inbox/`，然后做 ingest；
  - 定期做 lint；
  - 写代码时可以直接在 `repos/<名称>/` 里启动 AI。
- 在 Claude Code 中，对话会自动导出，会话开始时会自动注入上下文，前提是 loom 的 Claude Code 增强层已经加载，可以用 `loom.py doctor` 查看。在其他工具中，会话开始时对 AI 说一句"这是 Loom 项目，先读 hot.md"，效果会更好。
