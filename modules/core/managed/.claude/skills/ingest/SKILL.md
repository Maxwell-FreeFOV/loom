# /ingest · 资料入库

参数（可选）：文件路径、目录、网址，或 `inbox`（默认）。

`$PY` 指 `.kb.json` 中 `python` 字段的值。所有路径都相对于知识库根目录。

## 步骤

1. **确定本次处理的范围**：列出待处理的资料，默认是 `20-Sources/inbox/` 下的全部文件。如果超过 5 份，先按与项目目标（见 `10-Brief/`）的相关程度排序，和用户确认本次处理哪些。其余资料只编目，状态标为"待读"。

2. **存放原件**：
   - 本地文件：移入 `20-Sources/raw/YYYY-MM/`，保留原文件名。如果文件位于知识库之外，就复制，不要移动用户的原文件。
   - 网页：抓取正文，保存为 `20-Sources/raw/YYYY-MM/<标题>.md`，frontmatter 中写 `type: source`、`url` 和 `fetched`（抓取日期）。
   - PDF、DOCX 等二进制文件：在同一目录下生成同名的 `.md` 提取文本，方便检索。PDF 可以用 PyMuPDF 提取。
   - 原件放入 `raw/` 之后不再修改。

3. **登记**：在 `20-Sources/sources-index.md` 的表格中加一行，填写编号、资料（链接）、类型、来源、入库日期、状态和一句话摘要。

4. **写资料卡**（只针对重要资料）：按 `90-Templates/资料卡.md` 在 `20-Sources/cards/` 下新建，写清要点、可信度，以及它与本项目的关系。如果是研究类项目的论文，改用 `90-Templates/文献卡.md`，放在 `30-Wiki/literature/` 下。

5. **整合进 wiki**：把新知识写进 `30-Wiki/` 的主题页。
   - 补充新的论断，并标注来源。
   - 与已有内容矛盾时，把双方并列写出来，并注明各自的来源，不要直接覆盖。
   - 必要时新建主题页。一份资料可能会影响多个页面。

6. **收尾**：
   - 把本次处理过的资料在 `sources-index.md` 中的状态改为"已消化"。
   - 在 `00-Hub/log.md` 中追加一行。
   - 运行 `$PY scripts/kb.py index`。
   - 提交：`git add -A && git commit -m "ingest: 资料名"`。
   - 向用户报告：新增了哪些资料和 wiki 页；最重要的 3 条新发现；与已有认识冲突的地方。
