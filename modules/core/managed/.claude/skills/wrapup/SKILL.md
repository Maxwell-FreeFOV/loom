# /wrapup · 会话归档

目标：以后的自己和 AI 不用重读原始对话，就能知道这次讨论得出了什么、改变了什么。

`$PY` 指 `.kb.json` 中 `python` 字段的值。所有路径都相对于知识库根目录（`.kb.json` 所在的目录）。

## 步骤

1. **导出对话，找出待归档的会话**
   - 先运行 `$PY scripts/export_session.py --all`，再运行 `$PY scripts/kb.py unarchived`。后者列出所有还没有被纪要引用的原始对话，通常包括本次会话，也可能有以前忘记归档的。
   - 逐个判断如何处理：
     - 有实质内容：写纪要。同一主题的多个会话可以合并成一份纪要。
     - 没有实质内容（试运行、闲聊、中途放弃）：在 `40-Sessions/notes/_skipped.md` 里加一行链接，不写纪要。
   - 如果待归档的会话超过 3 个，先把列表和处理建议交给用户确认。

2. **写会话纪要**：按 `90-Templates/会话纪要.md` 新建 `40-Sessions/notes/YYYY-MM-DD_主题.md`，日期用会话发生的日期。
   - `raws` 字段中列出对应的原始对话链接，如 `raws: ["[[2026-01-01_1030_abcd1234]]"]`。
   - `tags` 用 3 到 6 个标签，便于以后 grep。
   - 只写实质内容：结论、洞察、分歧和行动，不要复述对话过程。用户的关键原话可以少量引用。

3. **写决策记录**（本次形成了决定，或者明确出现了一个待决定的重要事项时才写）：
   - 编号：扫描 `40-Sessions/decisions/`，取当年最大编号加 1，格式为 `DR-YYYY-NNN`。
   - 按 `90-Templates/决策记录.md` 新建 `40-Sessions/decisions/DR-YYYY-NNN_主题.md`，并在纪要的 `decisions` 字段中链接它。
   - `review_date` 默认：可逆决策为 1 个月后，不可逆决策为 3 个月后。用户指定了日期的，以用户为准。
   - 信心度和"放弃了什么"必须填写。讨论中没有明确的，用 AskUserQuestion 问用户。

4. **更新 wiki**：本次形成的新事实、新理解、调研结论，写进 `30-Wiki/` 对应的主题页。没有合适的页面就按 `90-Templates/wiki页.md` 新建。每个论断都注明来源（资料卡、原始资料或本次纪要）。纪要中只保留结论和指向 wiki 的链接，避免同一内容在两处重复展开。

5. **更新时间线和路线图**：
   - 如果本次有里程碑（重要决定、阶段切换、产出物发布、代码里程碑、关键发现），在 `00-Hub/timeline.md` 末尾追加 `- YYYY-MM-DD · 事件 · [[链接]]`。没有里程碑就不追加。
   - 在 `00-Hub/roadmap.md` 中勾掉已完成的任务，加入新任务。已完成的里程碑移入 timeline。

6. **检查产出物的关联**（存在 `50-Outputs/` 时）：对本次修改过或作为依据的产出物，更新其 frontmatter 中的 `sources`、`decisions` 和 `updated`。如果本次正式发布了某个版本，按 LOOM-RULES 第 9 节打 tag，并记入 timeline。

7. **更新 `00-Hub/hot.md`**：
   - 更新"当前阶段"和"当前重点"；
   - "未决问题"中，加入新出现的问题，删掉已解决的问题；
   - 更新"最近的决定"；
   - 更新 frontmatter 中的 `updated`。
   - hot.md 控制在一页以内，因为每次会话开始时都会注入它。

8. **收尾**：
   - 在 `00-Hub/log.md` 的注释行下方追加 `- YYYY-MM-DD HH:MM · wrapup · [[纪要]] [[决策]]`。
   - 运行 `$PY scripts/kb.py index`，然后运行 `$PY scripts/kb.py lint`，修复本次引入的问题。
   - 提交：`git add -A && git commit -m "wrapup: 主题"`。
   - 向用户简要报告：生成或修改了哪些文件，以及 3 条以内的核心结论，并请用户确认有没有记错。
