# /close · 项目收尾

`$PY` 指 `.kb.json` 中 `python` 字段的值。

1. 先执行 `/wrapup` 的第 1 步，确认没有未归档的会话。如果有，先归档。
2. 问用户两个问题：这次是暂停（以后可能继续）还是结束？原因是什么？
3. 写复盘纪要 `40-Sessions/notes/YYYY-MM-DD_项目复盘.md`。frontmatter 中 `type: session`，`tags` 包含 `复盘`。内容包括：
   - 最初想做什么（引用 `10-Brief/`），实际做成了什么；
   - 关键决策回顾：逐条链接决策记录，说明哪些判断对了、哪些错了，是运气还是决策质量；
   - 产出物清单，以及各自的最终版本；
   - 可复用的经验；
   - 如果是暂停：重启需要满足什么条件，重启后第一步做什么。
4. 逐个填写待复盘的决策记录中的"复盘"段落，并把状态改为"已复盘"。
5. 更新项目状态：
   - `.kb.json` 的 `status` 改为 `paused` 或 `closed`；
   - `hot.md` 顶部写明状态和日期；
   - `timeline` 末尾追加 `- YYYY-MM-DD · 项目暂停/结束 · [[复盘纪要]]`；
   - `roadmap` 中未完成的任务标注"搁置"。
6. 运行 `$PY scripts/kb.py index` 和 `$PY scripts/kb.py lint`，然后提交 `close: 项目暂停/结束`。
7. 征得用户同意后，打 tag `closed-YYYY-MM-DD`。
